### 1.5 scan_* ports and line doubler

- `scan_mode` = mode the PLL is currently programmed for; `scan_ready` = lock + settled + applied==requested (x68k_video_clock.sv:77-92). In the CRTC, scanout reset is released only if `rstn && scan_ready && cfg_valid && c_mode==active_mode` (x68k_native_crtc.sv:95-100), so scanout stops during a PLL retune. `rt_mode` (= `pVideoMode` = `pix_mode`) feeds the request (X68000.sv:162,862,939). `scan_reset_out` (= `scan_rstn`) also resets the line doubler (X68000.sv:973; X68K_top.vhd:3616). `render_reset_n` (scan reset re-synced to vidclk) resets vidcont, sprite engine and line-buffer writes (x68k_native_crtc.sv:175-179; X68K_top.vhd:3657, 3910, 3986).
- **Line doubler** (rtl/VIDEO/x68k_linedoubler.sv, `status[77] & ~video_31k`, X68000.sv:942): on clk_scan; stores each input line (`ce_in` samples of {RGB, HS, HB}) into a 2×2048×26 buffer (:12-15), then replays the previous line twice per input line by sampling at `ce_in | half_ce` (CE midpoint, :269-272) → 15 kHz becomes ~31 kHz with doubled pixel CE; VS/VB carried per line (:315-320). It is a pixel-rate doubler in the scan domain, not a framebuffer.

## 3. The DDR3 interface (rtl/memory/tvram_ddr.sv)

- Only TVRAM uses DDR3 (since #68 f94bfc6, "cpu to sdram and tvram to DDR3"). Interface = MiSTer
  `DDRAM_*` Avalon-MM: 64-bit data, 29-bit qword address, 8-bit burstcount, byte enables,
  `DDRAM_BUSY` = waitrequest (tvram_ddr.sv:35-44; sys/sys_top.v:1823-1832). Base `0x06000000`
  qwords (= byte 0x3000_0000) (:47). Clock = rclk 80 MHz (:159). 512 KB used = 64K qwords.
- Layout: one 64-bit qword = the same 16-pixel word of all 4 planes (plane p = lane p,
  `select_word`, :121-131). CPU word address bits [1:0] select the plane lane (set up by
  X68mmapCV.vhd:165-166).
- **Video reads t0/t1** (vidcont ping-pong by `ramsel`, vidcont.vhd:1282-1284): on a tag miss
  (tag = `t_addr[21:6]`, :79-80) burst **64 qwords = 512 B = one 1024-pixel text line, all 4
  planes** (:209-234, `BURSTCNT=64`), written into 4×64×16 caches per port (:85-109). One fill
  per rendered line → ≈16 MB/s at 31 kHz, ≈8 MB/s at 15 kHz (est.). Priority: t0 miss > t1 miss
  > raster copy > CPU RMW > CPU read > CPU write (:209-271). If t0 and t1 miss the same line both
  are filled by one burst (:213-217).
- **CPU**: single-qword (BURSTCNT=1) read (:255-261, 292-305), single-qword write with 2-of-8
  byte enables (:262-271, 307-317), RMW (mask register / simultaneous-plane writes) = read then
  write (:245-254, 319-347). CPU waits on `cpu_ack` (`cpu_done && cpu_req`, :118-119) — no
  posted writes, no CPU-side cache. Writes invalidate a cached video line with matching tag
  (:269-270, 344-345).
- **Raster copy**: request = 256-byte chunk (`cpy_src/dst[10:0]`): one 32-qword read burst into
  `cpy_buffer` (:235-244, 349-365) then **32 single-qword writes** with plane-mask byte enables
  (`plane_be`, :154-157, 367-384). rastercopy.vhd issues 8 chunks per CRTC raster-copy command
  (selwidth = 10-7 = 3) = 2 KB = 4 text lines × 4 planes; CPU is held by `iowait_rcpy`
  (X68K_top.vhd:3937) only when it writes the start bit while busy.
- Latency tolerance (est.): video fill must complete within roughly one line (ping-pong t0/t1,
  ≈31.8 µs at 31 kHz) — exact lead to be checked in vidcont; CPU reads/writes stall the 68000
  bus cycle (DTACK) for the full round trip; reset drain 255 idle clocks (:195-203).
- `rtl/ddram.sv` is **not used**: not in files.qip/X68000.qsf, no instantiation. It was the
  pre-#68 CPU main-RAM DDR3 backend (`ddram ddram_cpu_ram`, removed from X68000.sv in f94bfc6,
  together with menu `"P3O[68],CPU RAM,DDR3,SDRAM;"`; leftover: `status[68]` still triggers a
  reset in X68000.sv:525-527).

**Mapping options**

| Option | Assessment |
|---|---|
| (a) HyperRAM, Avalon 16-bit, ~100 MHz | Each qword = 4 beats; line fill = 256-beat burst (~2.6 µs + latency at 100 MHz, est.) — bandwidth fine (<10% of a line). Problems: shared with ascal (arbiter), ~9 cycles latency after CDC (AExp: AGENTS.md:636-639) and ~15-20 clocks per single transaction (AExp: doc/developers/history.md:1276); `hyperram_errata.vhd` turns single-word writes into 2-word bursts (AExp: doc/developers/floppy-adf.md:443). CPU single accesses and RMW become ≥200-400 ns + arbitration stalls (est.) → slower text drawing. Raster copy as 256 single writes would take tens of µs (est.) → must be rewritten as 128-beat masked burst writes. Needs avm_fifo CDC (80 MHz ↔ hr_clk) like Megamiga's RTG path (AExp: AGENTS.md:79, 620-621). Needs posted writes + small read cache to be acceptable. |
| (b) Block RAM | 128 tiles (§2.3). Deterministic: true dual port — port A CPU/raster copy (R/W, byte/plane masks), port B video fetch of 4 planes in parallel (64-bit wide or 4 × 16). Raster copy becomes a local 2 KB copy (~1k cycles). Simplest functionally; tightest on BRAM. |
| (c) SDRAM | The pre-#68 design kept TVRAM in SDRAM: memcont/cachecont still contain the `t0/t1` ports, the T caches and the `b_cpy`/ST_BCREAD raster-copy path (memcont.vhd:38-42,84-98; cachecont.vhd:850-853,906-909,914-951), currently tied off (X68K_top.vhd:3224-3228,3266-3280). Before #52 (33772fd) the SDRAM ran at **120 MHz** and carried main RAM + TVRAM + all GVRAM; #52 moved half GVRAM to BRAM and dropped to 80 MHz. MEGA65 SDRAM is proven at 113.5 MHz CL2 (AExp: CORE/Minimig_MiSTerMEGA65/rtl/sdram_ctrl.v:371; AGENTS.md:130-131). Viable if bandwidth is re-validated at ~113 MHz; zero HyperRAM dependency. |

## 4. SDRAM (rtl/memory/SDRAMC.vhd, memcont.vhd, cachecont.vhd)

- Generics from X68K_top.vhd:3194-3202: `AWIDTH=24` (word address → 32 MB), `CAWIDTH=9`,
  `BRSIZE=7`, `BRBLOCKS=16`, `CLKMHZ=RCFREQ=80` (X68K_top.vhd:9), `REFINT=10`, `REFCNT=64`;
  SDRAMC gets `LAWIDTH=8` (memcont.vhd:347-351).
- Geometry: bank = word-addr[23:22] (SDRAMC.vhd:121); row = 13 bits word-addr[21:9]
  (:124); column = 9 bits [8:0] driven as `"00" & '0' & C(9:0)` → A10=0 (no auto-precharge),
  A9=0 (:136-139, 256, 344). → 4 banks × 8192 rows × 512 cols × 16 bit = 32 MB (matches the
  MiSTer 32 MB SDRAM module, 4×8K×512). Bank map: main RAM + ROM + GVRAM-upper in banks 0-1;
  disk areas (addr bit 23 = 1) in banks 2-3.
- Mode register `"0000000100111"`: **CAS latency 2, sequential, full-page burst** (:231);
  bursts are cut with PALL (:300-310). Reads issue READ every block wrap and loop until
  `endaddr` (:246-298), up to 256 words/burst. Init: 1000-clock NOP + 2 µs wait, PALL, 20
  refreshes (`INITR_TIMES`), MRS (:80-87, 179-245).
- **DQM is driven from address bits**: `PMEMUDQ <= MADDR(12)`, `PMEMLDQ <= MADDR(11)`
  (:408-409); write byte masks are put on MADDR(12:11) during WRITE (:344, 352). `CKE=1`,
  `CS_n=0` constant (:404-405). Read data registered on rising clk (:415) with SDRAM_CLK
  inverted (X68000.sv:171-194) — timing relies on the 180° clock.
- Refresh is **operation-count based**, not time-based: idle cycles issue refresh and bank
  credit up to 63; every other operation consumes a credit; forced refresh when credit hits 0,
  then credit = REFINT-1 = 9 (cachecont.vhd:732-735, 1060-1066, 1077-1090). Worst-case refresh
  interval under load is therefore bounded by ~10 operations of up to ~270 clocks (est.), not by
  tREFI.
- Masters arbitrated in cachecont ST_IDLE (cachecont.vhd:730-1040, priority order):
  forced refresh → CPU write-buffer flush hazard → urgent CPU read (low area `sb_addr(22:17)`
  check) → video-hazard flush → **GVRAM upper-half plane reads g00..g13** (8 ports, 2×256-word
  `dual_phase` fills, :1068-1080) → (t0/t1 TVRAM — disabled) → raster copy `bcpend` (disabled,
  b_cpy='0') → CPU write-back → CPU read miss (16 × 128-word blocks) → GVRAM fast clear
  (`g*_clear`, direct or read-modify-write via GCLRBUF, :995-1027) → D88 track buffer (FDE
  read/write, :1029-1040) → FEC (SASI cache) read/write → idle refresh. The ROM loader writes
  through the CPU path (`ldr_*` → X68mmapCV → `ram_wr`, X68mmapCV.vhd:161,177,192-193).
- MEGA65 IS42S16320 (32M×16, 13-bit row, 10-bit column, 4 banks, 64 MB): SDRAMC's command
  format already carries 10 column bits; with `CAWIDTH=9` it simply uses half the device (A9=0).
  Using all 64 MB would need AWIDTH=25 and CAWIDTH=10 (not needed: X68000 uses <32 MB). Pin
  differences: separate DQM pins exist on both boards. CL2 at 80 MHz is conservative; at
  113.5 MHz CL2 is used by Megamiga on the same chip (AExp sdram_ctrl.v:371). tREFI for 8192
  rows/64 ms = 7.8 µs must be re-checked against the count-based scheme above.

## 5. HPS (hps_io) dependencies → what M2M/QNICE must supply

hps_io instance: X68000.sv:238-293 (`PS2DIV=2400`, `PS2WE=1`, `VDNUM=8`, default `BLKSZ=2` =
512-byte blocks, sys/hps_io.sv:28,35).

### 5.1 Virtual drives (sd_*)

| Slot | Menu (X68000.sv) | Type / format | Emulator |
|---|---|---|---|
| 0 | `P1S0,D88XDFDIMHDM,FDD0` (:65) | floppy | D88 → `diskemu` (bit-level FDC + MFM, image cached in SDRAM); XDF/DIM/HDM → `diskemu_misterFDC` (sector-level, 512 B dpssram) |
| 1 | `P1S1,…,FDD1` (:69) | floppy | same |
| 2 | `SC2,HDF,SASI Hard Disk` (:75) | SASI HDF | diskemu sasi path (`sasi_cap <= img_size`, diskemu.vhd:825-830) |
| 3 | `P3SC3,RAM,SRAM` (:82) | 16 KB SRAM image (default `boot3.vhd`) | sramcont via sramram; load/save by `status[13]/[14]` (:83-84, 678-679) |
| 4-7 | `SC4..SC7,HDS,SXSI Hard Disk 1-4` (:76-79) | SCSI HDS | diskemu sxsi (`sasi2..5_cap`, diskemu.vhd:834-870) |

- Signals: shared `sd_lba` (32-bit, replicated to all 8), `sd_rd/sd_wr/sd_ack[7:0]`,
  `sd_buff_addr[8:0]`, `sd_buff_dout/din[7:0]`, `sd_buff_wr`, `img_mounted[7:0]`,
  `img_readonly`, `img_size[63:0]` (X68000.sv:219-230, 249-260). All in clk_sys domain.
- Mount logic (X68000.sv:451-536): every `img_mounted` pulse starts a 24-bit `mount_count`
  (0xFFFFFF ≈ 0.42 s) and the core sees a **level** `img_mounted_d` while it runs (:457-466);
  `disk_present[x] <= |img_size`. FDD eject (`status[11]/[12]`) → 65535-clock `fdd_eject_count`
  and clears `disk_present` (:504-515). After every reset, present drives are re-announced
  (mount_count=0xFFFF, plus 1-cycle `post_reset_mount`) (:496-502, 810). Mounting the SASI HDF
  (slot 2) forces a 65535-clock reset (:521-523); so do toggles of `status[67]` (MIDI) and the
  stale `status[68]` (:525-531).
- D88 vs XDF mode: `disk_mode_r <= |ioctl_index[7:6]` when slot 0/1 mounts with size≠0
  (X68000.sv:737-743) — i.e. the index of the chosen extension (D88=0, XDF/DIM/HDM≠0) that MiSTer
  passes in ioctl_index bits 7:6 (inferred from this usage). `disk_mode` reroutes sd_ack/rd/wr/
  lba/buffdin and the SRAM RAM between the two emulators (X68000.sv:817; X68K_top.vhd:5188-5218).
  M2M equivalent: `img_type_o[1:0]` of vdrives (AExp: M2M/vhdl/vdrives.vhd:133).
- FDD write-back: "Save FDDx changes to SD" `status[9]/[10]` → `pFDSYNC` (X68000.sv:66,70,676,831).
- M2M must supply: vdrives with VDNUM=8 (MiSTer-compatible, AExp: M2M/vhdl/vdrives.vhd:117-160)
  but note: img_size is only 32-bit there, sd_*/sd_buff run in the **QNICE clock domain**
  (vdrives.vhd:150-170) → CDC or re-clocking of sectram/dpssram port A; HDF/HDS images (up to GB)
  cannot be pre-loaded into a buffer → need a direct SD-sector service (Megamiga precedent: direct
  SD block I/O 0.1.2, `ide_engine.vhd` 0.6.1, AExp: AGENTS.md:69, 112, 141); D88 images are
  sector-streamed into SDRAM by the core itself (diskemu.vhd es_fload*/es_fsave*, :134-143,
  1142-1153).

### 5.2 ioctl downloads (ROM loader)

- No `F` entries in CONF_STR: only MiSTer's automatic `boot.rom` (index 0). Any download goes
  to ROM space: `ldr_addr = ioctl_addr[19:0]`, `ldr_aen = ioctl_download & ~ldr_done`
  (X68000.sv:790-795). Handshake: `ldr_wr` set on `ioctl_wr`, cleared on `ldr_ack` rising edge;
  `ioctl_wait = ldr_wr` (:269, 884-897). `ldr_done` latches at the end of the first download and
  is never cleared. CPU reset is held until `ldr_done` (X68K_top.vhd:2829); `reset_n` is set at
  download start (X68000.sv:483).
- Content: 1 MB = F00000-FFFFFF (§2.1): CGROM 768 KB + 128 KB hole + IPL 128 KB, written
  byte-wise as `ldr_wdat & ldr_wdat` with `ram_wr` "10"/"01" (X68mmapCV.vhd:161,177,192-193) into
  SDRAM word 0x780000+.
- `ioctl_index` meanings: 0 = boot.rom; bits [7:6] read at floppy mount (above). Nothing else.

### 5.3 RTC
`sysrtc[64:0]` (MSM6242B layout from hps_io, sys/hps_io.sv:163-164) → `rp5c15 RTCIN`
(X68K_top.vhd:4741-4755). M2M supplies the same 65-bit format as `main_rtc_i` (AExp:
CORE/vhdl/mega65.vhd:204; main.vhd:312-316).

### 5.4 Keyboard and mouse
- hps_io emulates PS/2 wires (`PS2DIV=2400`, `PS2WE=1` bidirectional) (X68000.sv:238, 276-283);
  sampled with sys_ce (X68K_top.vhd:4723-4735).
- **Keyboard**: the X68000 keyboard is a serial device on the MFP USART; here `KBCONV`
  (inside MFP, MFP.vhd:528-562) replaces the USART register interface (RXED→INTA4, TXEMP→INTA2)
  and converts PS/2 set-2 codes via `PS2IF` (KBCONV.vhd:211) and the ROM tables `ktbln_m` /
  `ktble0_m` (E0-prefixed) indexed by `rom_kbdtype & code` (KBCONV.vhd:555-561); layouts from
  `status[36:34]` (MiSTer, JP Func., JP Pos., US Std, US Alt; X68000.sv:115, 681). `ps2_key`
  (X68000.sv:232,285) is unused. M2M offers only the MEGA65 matrix scan `kb_key_num`/
  `kb_key_pressed_n` (AExp: mega65.vhd:164-165) → needs a matrix→PS/2 encoder or a new
  matrix→X68000-keycode table feeding KBCONV.
- **Mouse**: SCC channel B fed by `MOUSECONV` (PS/2 mouse → X68000 serial packets, SCC/scc.vhd:
  257-266; MOUSECONV.vhd). MEGA65 has no PS/2 mouse; needs DB9 (1351/Amiga quadrature) → packet
  converter.

### 5.5 Joysticks
- `joystick_0/1[15:0]` + `joystick_l/r_analog_0` (X68000.sv:216-217, 289-292). Bits: 0-3 dirs,
  4 B1, 5 B2, 6 Run, 7 Select, 8-11 B3-B6 (CONF_STR J line, :123). Swap `status[43]`, per-port
  type `status[39:37]`/`[46:44]`: 2-button, 2-turbo (VBlank-based repeat, :310-329),
  MegaDrive 3, Magical 6, Capcom 6, Double-DPad, CyberStick (XE1AP, port A only) (:112-113,
  340-416, 426-447). Strobe outputs come from PPI port C (`pJoySelA/B`, X68K_top.vhd:4362-4365);
  pins into PPI A/B (:4360-4361).
- MEGA65/M2M: two DB9 ports (4 dirs + fire, plus pots) (AExp: mega65.vhd:179-188); no USB pads,
  no analog sticks → only 1-2 button modes natively; MD/6-button/CyberStick need physical pads
  driven through the strobe line (pin-level work, unverified).

### 5.6 Status bits used (CONF_STR X68000.sv:61-140; decode :49-51, 674-691, 875-881)
0 reset · 3:2 stereo mix (`AUDIO_MIX`) · 5:4 aspect · 7 NMI · 8 power · 9/10 FDD0/1 sync ·

### 5.7 UART / MIDI / USER_IO / MT32-pi
- CONF_STR `"UART115200,MIDI"` (:62). `UART_RXD → pMidi_in`, `pMidi_out → UART_TXD` (YM3802
  `em3802` at EAFA00, enabled by `status[67]`, else bus error) (X68000.sv:846-847;
  X68K_top.vhd:4764-4804). `mt32pi` (sys/mt32pi.sv) uses USER_IO via `.*`, receives MIDI from
  `UART_TXD` or an "all notes off" injector after reset (X68000.sv:538-620), adds its I2S audio
  (:922-926) and an OSD LCD overlay (:636-669, 967-968). MEGA65: no USER_IO/HPS UART; PMOD is the

### 5.8 Audio out
16-bit signed (`AUDIO_S=1`, X68000.sv:694). Core: OPM (jt51 or IKAOPM, `status[58]`) /2 + ADPCM
saturating add (`addsat`) at clk_sys (X68K_top.vhd:4680-4698); L/R deliberately swapped at the
top (`pSndL => aud_r`, X68000.sv:865-866). `out = aud + mt32_i2s` at CLK_AUDIO without CDC
(:922-929). M2M: `main_audio_left/right_o` signed 16-bit (AExp: mega65.vhd:160).

### 5.9 Video out
- From X68K_top (clk_scan): `pVideoR/G/B[7:0]` (6-bit + contrast → 8, X68K_top.vhd:3623-3625),
  `pVideoHS/VS` active-high (mister_sync.sv:130-131), `pVideoHB/VB` = CRTC blank, "native box"
  blank or syncs depending on `status[70:69]` (X68K_top.vhd:3640-3646), `pVideoEN` (DE),
  `pVideoClk` = 1-clock CE (:3637-3638), `pVideoF1` → `VGA_F1` = constant 0
  (x68k_native_crtc.sv:144), `pVideo31k`, `pVideoMode` (PLL request).
- Top chain (X68000.sv:933-1024): MT32 overlay → optional line doubler → `video_mixer`
  (LINE_LENGTH 800, no scandoubler/hq2x, GAMMA 0) → `video_freak` (ARX/ARY 4:3 or full,

- M2M constraints to respect: active-high syncs, blanks covering syncs, video_mixer
  LINE_LENGTH=768 and ascal IHRES=1024 (AExp: AGENTS.md:438-442). X68000 active widths go to 768
  at 34.776 MHz pixel CE; the core itself uses LINE_LENGTH 800.

## 8. Risks and unknowns (ranked)

1. **Memory architecture without DDR3** (§3/§4). TVRAM needs 512 KB with 4-plane parallel video
   fetch, masked CPU writes/RMW and raster copy. HyperRAM is shared with ascal and has 15-20-clock
   per-transaction overhead → CPU stalls and slow raster copy unless tvram_ddr is redesigned
   (posted writes, burst masked writes). BRAM costs 128 tiles (≈294-321/365 total, est.). SDRAM
   (pre-#68 path still in cachecont) needs ~113-120 MHz and a bandwidth re-check with GVRAM-upper,
   CPU caches and disk on the same chip. The count-based refresh needs re-verification for
   IS42S16320 at the chosen clock.
2. **Video clocking and M2M video path**. Four exact oscillator frequencies via a run-time
   retuned PLL (pll_native + Cyclone-V pll_cfg) → MMCM DRP or multi-MMCM + BUFGMUX; scanout
   restarts on every mode change; M2M expects one core video clock domain feeding ascal and the
   analog scandoubler (line limits 768/1024, AExp: AGENTS.md:438-442), while X68000 uses 15/24/31
   kHz and pixel CEs up to 34.776 MHz with LINE_LENGTH 800. Fallback: the old fixed-80 MHz
   polyclock mode still in mister_sync (shimmering, the reason for #72).
3. **Storage / HPS replacement**. Eight MiSTer virtual drives with exact mount/eject/re-mount
   timing (§5.1), D88 write-back, XDF/DIM/HDM, multi-GB SASI/SxSI images with random sector
   access, SRAM image load/save, 1 MB boot.rom into SDRAM before CPU release. M2M vdrives is
   QNICE-clocked, 32-bit size, and its buffered model does not fit HDF/HDS → direct SD block
   engine needed (Megamiga ide_engine is the precedent).
4. **Licensing**. Puu-san's RTL (most of the core) carries no licence grant beyond a Japanese
   "free software" statement with retained rights; IKAOPM, xe1ap, mister_sync have no licence
   text; fx68k/jt51 are GPL-3+, the top is GPL-2+. Combined redistribution terms are unclear
   until Puu's intent (and IKAOPM's upstream licence) is confirmed. ROM images must not ship
   without permission.
5. **BRAM / timing on XC7A200T-2**. Firm core ≈120.5 tiles (est.) before TVRAM; 40 tiny TDP
   CACHEMEMN RAMs waste 20 tiles on Xilinx; GVRAM half alone is 64. Megamiga already closes at
   only +0.02…+0.3 ns (AExp: AGENTS.md:433-437); here cachecont (1719 lines) at 80 MHz, fx68k
   at 40 MHz and the inverted-clock SDRAM interface with DQM on address bits (SDRAMC.vhd:408-409)
   must close on Artix-7 with new IO constraints.
6. **Input devices**. Keyboard path is PS/2→KBCONV (MFP-USART emulation) with layout ROMs;
   MEGA65 gives a key matrix only. Mouse needs DB9→X68000-packet conversion. Multi-button
   joystick modes and CyberStick depend on USB-pad bits and analog sticks that MEGA65 lacks.
7. **CDC hygiene that MiSTer tolerates**: audio sampled from clk_sys on CLK_AUDIO without
   synchronisers (X68000.sv:922-926); MFP GPIP/timer inputs from the 80 MHz render domain
   (X68K_top.vhd:4384-4392); vdrives in QNICE domain vs sector RAMs on clk_sys; scanout async reset
   from combinational logic.
8. **MIDI/MT32-pi/UART** have no MEGA65 counterpart except a PMOD; low priority.
9. **Leftovers to clean during the port**: `status[68]` reset trigger, stale VLBUF SDC false
   paths, `.outclk_2()` on a nonexistent port, `dHMode/dVMode` wired to joystick bits but unused,
   dead TVRAM ports in memcont, unused files in the .qip lists (VLINEBUF, nvram, fontrom, CRTCX68TXT
   group, ddram.sv in rtl/).
